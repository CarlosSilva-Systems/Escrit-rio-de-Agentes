# Referência: internacionalização (i18n)

[🇺🇸 English](../../en/reference/i18n.md) · [Índice da documentação](../README.md)

Idiomas: português (Brasil, `pt-BR`, o padrão) e inglês (`en`). O texto da interface nunca fica no código: passa por um dicionário.

## Onde ficam os textos

| Camada | Fonte | O idioma é escolhido por |
|---|---|---|
| Interface web | `src/web/i18n/pt-BR.json` (fonte das chaves) e `src/web/i18n/en.json` | O botão da barra superior; a escolha fica salva no `localStorage` do navegador (chave `escritorio.lang`) e no `config.json` por meio do `PATCH /api/config`, então vale também em outro navegador. O primeiro carregamento é sempre `pt-BR`, nunca o idioma do navegador. Trocar não recarrega a página. |
| Mensagens do servidor (erros, partida, base da CLI) | `src/server/i18n/pt-BR.ts`, `src/server/i18n/en.ts` | `lang` em `%USERPROFILE%\.escritorio-equipe\config.json` |
| Mensagens de `settings:*` e `hooks:sync` | `src/cli/settings/messages.ts` | o mesmo `lang` |
| Mensagens e diagnósticos de `team:*` | `src/cli/team/messages.ts` | o mesmo `lang`, ou `--lang pt-BR\|en` |

Texto que vem de dados aparece como está e nunca é traduzido: nomes de pastas, títulos de tarefas, apelidos, cargos e frases do `escritorio.json`.

## Regras

- O `pt-BR.json` define as chaves. O `en.json` precisa ter exatamente o mesmo conjunto de chaves, nenhum valor vazio e os mesmos `{marcadores}`. Um teste unitário (`src/web/i18n/i18n.test.ts`, CA-10) falha caso contrário.
- Uma chave ausente num idioma cai para `pt-BR` e depois para a própria chave. Um marcador sem valor continua visível como `{nome}`.
- O relógio sempre usa o fuso do estúdio (`America/Sao_Paulo`); números e datas seguem o idioma.
- Os catálogos do servidor e da CLI têm o mesmo conjunto de chaves nos dois idiomas, também garantido por testes.

## Adicionar um texto

1. Acrescente a chave ao `pt-BR.json` e depois a mesma chave ao `en.json`.
2. Use no componente com `t('sua.chave', { nome: valor })`.
3. Rode `npm run test:unit`.

## Adicionar um idioma

Um terceiro idioma não é só tradução, porque a lista de idiomas faz parte dos contratos. Para um idioma `xx`:

1. Copie `src/web/i18n/pt-BR.json` para `xx.json`, traduza os valores (mantendo chaves e marcadores) e acrescente uma entrada `lang.xx` (nome do idioma) a todos os dicionários.
2. Em `src/web/i18n/i18n.ts`, acrescente `xx` a `Lang`, `LANGS`, `dictionaries` e `isLang`.
3. Em `src/shared/contracts/state.ts` (`PublicConfigSchema.lang`) e `src/shared/contracts/rest.ts` (`SessionResponseSchema`), acrescente `xx` aos valores permitidos e rode `npm run schemas:gen`.
4. Acrescente um catálogo para `xx` em `src/server/i18n/`, `src/cli/settings/messages.ts` e `src/cli/team/messages.ts`.
5. O botão da barra superior alterna entre exatamente dois idiomas (`pt-BR` e `en`); com três ou mais ele precisa virar um menu (`src/web/hud/topbar/Topbar.tsx`).
6. Estenda os testes de paridade para comparar `xx` com `pt-BR` e rode `npm run check`.

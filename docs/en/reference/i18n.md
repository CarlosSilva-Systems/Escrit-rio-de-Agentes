# Reference: internationalization (i18n)

[🇧🇷 Português](../../pt-BR/reference/i18n.md) · [Documentation index](../README.md)

Languages: Portuguese (Brazil, `pt-BR`, the default) and English (`en`). Interface text never lives in the code: it goes through a dictionary.

## Where the texts live

| Layer | Source | Language is chosen by |
|---|---|---|
| Web interface | `src/web/i18n/pt-BR.json` (source of the keys) and `src/web/i18n/en.json` | The top-bar button; the choice is saved in the browser's `localStorage` (key `escritorio.lang`) and in `config.json` through `PATCH /api/config`, so it also follows you to another browser. The first load is always `pt-BR`, never the browser's language. Switching does not reload the page. |
| Server messages (errors, start-up, CLI base) | `src/server/i18n/pt-BR.ts`, `src/server/i18n/en.ts` | `lang` in `%USERPROFILE%\.escritorio-equipe\config.json` |
| `settings:*` and `hooks:sync` messages | `src/cli/settings/messages.ts` | same `lang` |
| `team:*` messages and diagnostics | `src/cli/team/messages.ts` | same `lang`, or `--lang pt-BR\|en` |

Text that comes from data is shown as it is and never translated: folder names, task titles, nicknames, titles and phrases of `escritorio.json`.

## Rules

- `pt-BR.json` defines the keys. `en.json` must have exactly the same set of keys, no value empty, and the same `{placeholders}`. A unit test (`src/web/i18n/i18n.test.ts`, CA-10) fails otherwise.
- A key missing in a language falls back to `pt-BR`, then to the key itself. A placeholder with no value stays visible as `{name}`.
- The clock always uses the studio time zone (`America/Sao_Paulo`); numbers and dates follow the language.
- Server and CLI catalogs have the same key set in both languages, also enforced by tests.

## Add a text

1. Add the key to `pt-BR.json`, then the same key to `en.json`.
2. Use it with `t('your.key', { name: value })` in a component.
3. Run `npm run test:unit`.

## Add a language

Adding a third language is not only a translation, because the list of languages is part of the contracts. For a language `xx`:

1. Copy `src/web/i18n/pt-BR.json` to `xx.json`, translate the values (keep keys and placeholders) and add a `lang.xx` entry (language name) to every dictionary.
2. In `src/web/i18n/i18n.ts`, add `xx` to `Lang`, `LANGS`, `dictionaries` and `isLang`.
3. In `src/shared/contracts/state.ts` (`PublicConfigSchema.lang`) and `src/shared/contracts/rest.ts` (`SessionResponseSchema`), add `xx` to the allowed values, then run `npm run schemas:gen`.
4. Add a catalog for `xx` in `src/server/i18n/`, `src/cli/settings/messages.ts` and `src/cli/team/messages.ts`.
5. The top-bar button toggles between exactly two languages (`pt-BR` and `en`); with three or more it must become a menu (`src/web/hud/topbar/Topbar.tsx`).
6. Extend the parity tests to compare `xx` with `pt-BR`, then run `npm run check`.
